# 열기지도 프로젝트 기획 (단디톤)

2026-11-01 · 김재민

## 한 줄 소개

대구 원도심과 공연장·경기장에서 **"지금 살아 있는 현장"을 온도로 보여주는** 모바일 웹앱. 방문객이 명소 한 곳에서 다음 골목, 다음 가게로 이어가게 만든다.

---

## 1. 문제와 목표

**문제**
- 대구를 찾는 사람은 늘었지만, 대표 명소만 보고 떠난다.
- 그래서 체류 시간과 소비가 골목 상권까지 이어지지 않는다.
- 가장 큰 이유는 **지금 어디가 살아 있는지 보이지 않기 때문**이다.

**목표**
- 현장에 있는 사람이 "열기"를 올린다.
- 서버가 장소별 온도를 계산한다.
- 지도에 바로 반영된다.

이 고리가 처음부터 끝까지 돌아가는 것이 MVP의 기준이다.

**대상**
- 동성로·서문시장·김광석길·근대골목 등 원도심 구역
- 공연장(콘서트홀·극장·소극장)
- 경기장(야구장·축구장)

---

## 2. 핵심 컨셉: 구역(동네) → 매장

열기는 **매장(장소) 단위로 모으고**, 지도에서는 **구역(작은 동네) 단위로 먼저 보여준다.**

```
[지도 첫 화면]  동네 크기의 원 + "구역 이름 · 온도"
      │  구역을 누르면
      ▼
[구역 확대]    그 안의 매장 마커 + 하단에 매장 목록 (뜨거운 순)
      │  매장을 누르면
      ▼
[매장 상세]    현재 온도 · 6시간 그래프 · 사람들이 남긴 사진과 글
               → "열기 올리기" / "여기서 다음 갈 곳"
```

**이렇게 잡는 이유**
- **"명소에서 다음 골목으로"라는 목표에 맞는다.** 뜨거운 동네를 보고 가서, 그 안에서 가게를 고르는 흐름이 된다.
- **초반 데이터 부족을 덜 수 있다.** 사용자가 적은 초반에는 매장 하나하나의 반응이 적다. 구역으로 합쳐 보여주면 지도가 비어 보이지 않는다.
- **구역 온도 계산:** 구역 안 모든 매장의 반응을 합쳐서 같은 엔진으로 계산한다. 같은 동네에 동시에 모인 사람도 함께 반영된다.

**초기 구역**

| 종류 | 구역 |
| --- | --- |
| 원도심 동네 | 동성로, 서문시장, 근대골목, 김광석길, 교동, 동인동, 북성로·수창동, 봉산문화거리, 칠성시장, 평화시장 |
| 공연장·경기장 | 삼성라이온즈파크, 대구iM뱅크파크, 대구오페라하우스, 엑스코, 대구문화예술회관 |

공연장·경기장은 장소 하나로 된 구역이다. 누르면 바로 매장 상세가 열린다.

## 3. 카테고리

| 카테고리 | 예시 | 평소값 B |
| --- | --- | --- |
| 맛집 | 찜갈비골목, 떡볶이집, 국밥집 | 5 |
| 카페 | 미도다방, 골목 카페 | 5 |
| 거리 | 김광석길, 3.1만세운동길, 진골목 | 8 |
| 시장 | 서문시장, 칠성시장, 교동시장 | 10 |
| 야시장 | 서문시장 야시장, 칠성야시장 | 12 |
| 공연 | 콘서트하우스, 오페라하우스, 엑스코, 영화관, 소극장 | 15 |
| 축제 | 2.28공원, 국채보상공원, 버스킹 광장 | 20 |
| 경기장 | 삼성라이온즈파크, 대구iM뱅크파크 | 20 |

- **시장과 야시장은 따로 구분한다.** 같은 시장이라도 낮과 밤의 분위기가 다르다.
- **평소값 B는 "그 장소의 평소 반응 수준"이다.** 원래 사람이 많은 곳일수록 높게 잡아서, 평소보다 얼마나 뜨거운지를 공정하게 비교한다. 현장 테스트 후 조정한다.

## 5. 열기 계산 방식

온도는 **"그 장소의 평소 대비 최근 30분 반응이 몇 배인가"**로 정한다.

```
온도 = 20 + 10 × min(최근 반응 R ÷ 평소값 B, 3) + 보너스
```

- 평소 수준이면 30°C, 2배면 40°C, 3배 이상이면 50°C다.
- 보너스: 행사 진행 중이면 +5, 검색 급증이면 +3

| 요소 | 규칙 |
| --- | --- |
| 1회 점수 | 연타 횟수(최대 40회)와 흔들기 세기로 0~1점 |
| 시간 감쇠 | 30분에 걸쳐 0으로 줄어든다 |
| 동시성 | 같은 곳에서 60초 안에 함께 올린 서로 다른 기기 수만큼 최대 2배 |
| 온도 단계 | 30°C 미만 미지근 · 30~40 따뜻 · 40~50 뜨거움 · 50 이상 **대프리카** |

**어뷰징 방지**
- 현장 150m 안에서만 올릴 수 있다.
- 같은 매장은 5분에 1회, 기기당 1시간에 20회까지 올릴 수 있다.
- 혼자서는 동시성 보너스를 받을 수 없다.

## 6. 데이터 확보 전략

### 6-1. 장소 데이터
- **명소·시장·공연장·경기장:** 기획팀이 CSV로 정리한다. 좌표는 카카오 장소 검색으로 자동으로 채운다.
  - 같은 이름의 다른 도시 장소가 잡히지 않도록 검색 범위는 대구 시내로 제한한다.
- **맛집·카페:** 구역마다 카카오 카테고리 검색으로 상위 매장을 자동으로 모은 뒤, 기획팀이 검토해서 빼거나 더한다.
- **초기 규모:** 구역 15곳, 장소 100곳 안팎

### 6-2. 초반 열기 데이터 (콜드 스타트)
지도가 전부 회색이면 서비스의 의미가 없다. 그래서 초반 반응을 모으는 것이 가장 큰 과제다.

1. **매장 QR 스티커**
   - 카운터의 QR을 찍으면 바로 열기 올리기 화면으로 간다.
   - 현장 인증이 확실해서 실내 GPS 오차와 어뷰징 문제가 같이 해결된다.
   - 사장님에게는 "우리 가게가 지도에서 빨개진다"가 홍보라 참여할 동기가 있다.
2. **시드 사용자**
   - 서포터즈나 상인회처럼 초반에 꾸준히 올려 줄 20~30명을 확보한다.
   - 축제·야시장·경기 날에 집중한다.
3. **외부 신호 활용**
   - 블로그 글이 최근 급증한 곳은 "검색 급증 +3°C"로 미리 따뜻하게 보여준다.
4. **발표 때는 데모 시뮬레이터**
   - 발표 30분 전에 지도 전체를 미지근~따뜻하게 데운다.
   - 클라이맥스에서 한 곳을 50°C 이상으로 터뜨린다.
   - 여기에 심사위원 폰 반응을 더한다.

### 6-3. 사람들이 남긴 사진·글

| 출처 | 방식 | 비고 |
| --- | --- | --- |
| 다음(카카오) 검색 | 사진 썸네일 9장 + 블로그 글 5건 | 카카오 키 하나로 가능 |
| 네이버 블로그 | 검색 페이지 바로가기 → 여유 시 공식 API | API는 별도 키 필요, 썸네일 없음 |
| 인스타그램 | 해시태그 페이지 바로가기 | API는 비즈니스 계정·앱 심사 필요. 긁어오기는 약관 위반 |

남의 사진은 앱 안에 크게 띄우지 않고 **썸네일과 원문 링크**로만 보여준다. 저작권 문제를 피하기 위해서다.

## 7. 기술 구성

| 영역 | 선택 | 이유 |
| --- | --- | --- |
| 프레임워크 | Next.js + TypeScript + Tailwind | 화면과 API를 한 저장소에서 개발 |
| DB | Supabase (Postgres, 서울 리전) | 테이블·대시보드 기본 제공 |
| 지도 | 카카오맵 SDK + 커스텀 오버레이 | 국내 지도 정확도, 마커를 자유롭게 디자인 |
| 장소·사진 검색 | 카카오 로컬 API, 다음 검색 API | 좌표 변환, 맛집 수집, 사진·블로그 |
| 실시간 | 5초 폴링 | 웹소켓 없이도 충분 |
| 배포 | Vercel (서울 리전) | HTTPS 기본 제공 (위치·센서 필수 조건), DB와 같은 지역 |

- **데이터:** 구역(zones), 장소(places), 열기 기록(heat_events) 세 테이블. 온도는 저장하지 않고 요청할 때마다 계산한다.
- **보안:** 브라우저는 DB에 직접 붙지 않고 항상 서버 API를 거친다. 어뷰징 검사를 서버에서 하기 위해서다.

## 8. 화면 구성

1. **지도 홈:** 구역 원과 온도, 카테고리 칩, "다음 갈 곳"과 "내 발자국" 버튼
2. **구역 시트:** 구역 온도와 매장 목록 (뜨거운 순)
3. **매장 시트:** 온도와 단계, 지금 올리는 사람 수, 6시간 그래프, 오늘 최고 온도, 사진·글, 버튼 2개
4. **열기 올리기:** 거리 확인 → 3·2·1 카운트 → 10초 연타 + 흔들기 → 결과 ("+2.3°C · 지금 5명이 같이 터뜨렸어요")
   - 50°C를 넘으면 전체 화면 **대프리카 모드**
5. **열기 코스:** 지도 위에 1·2·3 번호와 연결선, 하단에 이동 거리
6. **내 발자국:** 내가 열기를 올린 곳 지도와 목록

모바일 세로 화면이 기준이다.

## 9. 오늘 회의에서 정할 것

- [ ] **구역 → 매장 구조**로 확정할지

- [ ] **맛집·카페 선정 방식**: 자동 수집 + 검토로 갈지, 직접 고를지
- [ ] **카테고리별 평소값**: 특히 카페, 야시장, 공연
- [ ] **매장 QR**을 MVP에 넣을지, 시범 매장을 어디로 할지
- [ ] **네이버 블로그 API** 키 발급 여부 (팀 계정)
- [ ] **발표 기기**: 폰인지 노트북인지
- [ ] **역할 분담**과 **현장 테스트 일정**: 동성로에서 아이폰·안드로이드 각각, 폰 3대 이상

## 10. 리스크

- **실내 GPS 오차:** 시장이나 건물 안에서는 위치가 수십 m 튈 수 있다. 현장 테스트 후 150m 반경을 조정하고, 매장 QR로 보완한다.
- **아이폰 제약:** 흔들기 센서는 버튼 클릭 안에서만 권한을 요청할 수 있다. 진동은 지원되지 않아서 화면 효과로 대체한다.
- **초반 데이터 부족:** 6-2의 전략으로 대응한다.
- **외부 콘텐츠 저작권:** 썸네일과 원문 링크로만 보여준다.
