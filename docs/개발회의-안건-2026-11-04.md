## 안건 1. 열기 공식 개편 — 상시 장소의 "요즘 인기" 반영 `백엔드`

**배경.** 반응은 30분이면 0이 되어, 다음 날 첫 사용자에게는 지도가 전부 회색이다. 외부 트렌드 데이터를 뺐으므로 인기 신호는 앱 안에서 만들어야 한다.

**정할 것**
- 인기 신호 출처: ① 최근 7일 누적 열기 ② 커뮤니티 사진·댓글 수 ③ 둘 다
- 가중치: 인기 보너스 상한 (예: 최대 +5°C), 날짜별 감쇠 (예: 하루마다 절반)
- 하루 경계: 자정 vs 새벽 5시
- 적용 대상: 맛집·카페·거리·시장 등 상시 장소만? 공연·경기장 제외?

**추천.** ①로 시작, 커뮤니티 글 수는 이후 추가. 하루 경계는 새벽 5시 (동성로 밤 상권).

```
T = 20 + 인기 보너스(0~5) + 10 × min(R / B, 3) + E
```

- 계산 비용: 7일치 heat_events를 매 요청마다 읽을지, 하루 1회 집계해 places에 저장할지
- 단위 테스트 추가: 어제 반응 많았던 곳 → 오늘 아침 30°C 근처

## 안건 2. 일회성 열기 (콘서트·버스킹·경기) `백엔드` `프론트`

**배경.** 일정 데이터를 받아 하루가 지나면 열기를 초기화하기로 했다.

**정할 것**
- 일정 출처
  - 공연: KOPIS(공연예술통합전산망) 오픈 API — 공연장별 일정
  - 경기: 삼성라이온즈·대구FC 시즌 일정 CSV 직접 입력
  - 버스킹: 데이터 없음 → 수동 등록
- "초기화"의 정의 (열기는 이미 30분이면 사라지므로)
  - (a) 행사 당일은 열기를 하루 동안 쌓고, 다음 날 지운다
  - (b) 일정에 맞춰 행사 보너스(+5)를 자동으로 켜고 끈다
- 저장: `schedules` 테이블 (place_id, title, starts_at, ends_at, source) — 안건 6-4 참고
- 화면: 장소 시트에 "오늘 19:00 ○○ 콘서트" 표시, 행사 중 마커 표시

**추천.** (b) + 시작 1시간 전부터 보너스 적용. 가볍고 데모에서 바로 보인다.

## 안건 3. 커뮤니티 (사진 업로드 + 댓글) — 로그인 적용 `백엔드` `프론트`

**배경.** 다음 검색 사진·블로그를 사용자가 직접 올리는 사진과 댓글로 바꾼다. 커뮤니티는 **로그인한 사용자만 쓰도록** 바꾸는 안을 논의한다. 기존 명세의 "회원가입·로그인 제외"를 커뮤니티에 한해 바꾸는 범위 변경이다.

**로그인 적용 범위 (제안)**

| 기능 | 로그인 |
| --- | --- |
| 지도·장소 시트·사진·댓글 보기 | 필요 없음 |
| 열기 올리기 | 필요 없음 (익명 기기 ID 유지 — 심사위원이 바로 눌러볼 수 있게) |
| 사진 올리기·댓글 쓰기·신고·내 글 삭제 | **필요** |

- 로그인 수단: 카카오 로그인 (Supabase Auth 카카오 제공자, 기존 카카오 개발자 앱 사용)
- 동의 항목: 닉네임·프로필 사진만 (이메일 등은 추가 심사가 필요할 수 있어 제외)
- 브라우저는 로그인만 Supabase Auth로 직접 하고, 글쓰기는 API를 거친다 (브라우저 직접 DB 접근 금지 원칙 유지)

**좋아지는 점**
- 신고·쿨다운·숨김을 계정 단위로 → 기기 ID 재생성 우회 차단
- 댓글에 닉네임이 붙어 커뮤니티답게 보임, 내 글 삭제가 자연스러움
- 발표의 확장 계획("로그인 연동 시 계정 단위 제한")을 일부 실제로 보여줌

**비용과 위험**
- 작업량: 백엔드 2(토큰 검증, profiles), 프론트 2(로그인 버튼, 세션 유지, 로그인 후 원래 화면 복귀) 각각 반나절~하루 추가
- 카카오 콘솔: Redirect URI 등록, 동의 항목 설정
- Vercel 미리보기 주소는 배포마다 바뀌어 리다이렉트가 깨짐 → 고정 프로덕션 주소로 테스트
- 데모: 심사위원이 사진을 올리려면 카카오 로그인 필요 → 발표는 미리 로그인한 폰으로 시연
- 닉네임·프로필 저장 시 개인정보 처리방침 필요 여부 확인 (기획)

**대비책.** 11/6 오전까지 로그인이 안정적이지 않으면 익명 `deviceId` 방식으로 되돌린다. 쓰기 API가 처음부터 둘 다 받을 수 있게 설계해 되돌리는 비용을 줄인다.

**정할 것**
- 로그인 적용 범위: 커뮤니티 쓰기만 (추천) vs 열기 올리기까지
- 로그인 수단: 카카오만 (추천) vs 추가 수단
- 작성 조건: 장소 150m 안에서만 작성? (열기 올리기와 같은 규칙 → 현장 인증)
- 관리: 신고 n건이면 자동 숨김, 사진 용량·압축 (클라이언트에서 리사이즈 후 업로드)
- 저장소: Supabase Storage 버킷, 업로드는 서버 API 경유 (브라우저 직접 DB 접근 금지 원칙 유지)
- 다음 검색 사진·블로그(`/api/places/[id]/posts`)는 **삭제 확정** (11/1 회의). 인스타·네이버 바로가기도 이 API에 들어 있어 함께 없어진다
- 범위: 사진 + 댓글 둘 다 vs 사진만

**추천.** 커뮤니티 쓰기에만 카카오 로그인, 사진은 현장 150m 제한 적용. 4명이면 사진·댓글 둘 다 가능하나, 댓글은 3일 차 끝까지 안 되면 제외.

## 안건 4. 지도 B 대비 개발 준비 `프론트`

**배경.** 디자이너 회의에서 최종 결정. B로 가면 지도 컴포넌트를 다시 만든다.

**정할 것**
- 디자이너 결정 마감 시각 (프론트 일정이 여기에 묶임)
- 시안 전까지 SVG 임시 지도로 먼저 검증
- 좌표 변환: 지도 이미지 기준점 2~3개 → 비례식, 지도 경계(남북·동서 끝 좌표)를 기획과 확정
- 재작업 범위: KakaoMap · HeatMarker · ZoneLayer · CourseLayer, 줌은 `react-zoom-pan-pinch`
- 길찾기: 카카오맵 링크(`map.kakao.com/link/to/...`) 버튼으로 대체
- 카카오 로컬 API 약관 확인 결과 (기획)
