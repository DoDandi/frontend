# 와이어프레임 검토 결정 사항

2026-11-07 · [피그마 와이어프레임](https://www.figma.com/design/oSgbD5Fcizxt6WPtySdU8p/?node-id=15-6) 기준

> **진행 원칙**: 개발은 **기능을 넣을지 말지**와 그 동작 규칙만 정한다. 화면 구성(레이아웃, 문구, 새 화면 추가)은 **디자인 파트와 협의한 뒤** 진행한다. 아래에 적힌 "디자인에 추가할 것"은 협의할 때 전달할 요청 사항이다.

## 1. 열기 숫자 단위 — 확정

**도(°) 단위, 실제 날씨 감각에 맞춘다.**

```
T = 10 + 10 × min(R / B, 3) + E (+ 인기 보너스)
```

| 상황 | 열기 |
| --- | --- |
| 반응 없음 | 10° |
| 평소 수준 | 20° |
| 평소의 2배 | 30° |
| 평소의 3배 이상 | 40° |
| 최대 (일정 +5, 인기 +5 포함) | 50° |

| 열기 | 단계 | 날씨로 치면 |
| --- | --- | --- |
| 20° 미만 | 서늘 | 쌀쌀한 날 |
| 20~30° | 따뜻 | 초여름 |
| 30~40° | 폭염 | 한여름·폭염특보 |
| 40° 이상 | 대프리카 | 대구 기록급 |

**표시 규칙**
- API는 지금처럼 소수 첫째 자리(0.1°)까지 돌려준다.
- 지도 마커·목록·장소 상세는 정수(예: 32°)로 표시한다.
- 06 결과 화면의 오른 양은 소수 첫째 자리(예: +0.8°)로 표시하고, 함께 올린 사람 수를 같이 보여준다.
- 숫자 옆에 🔥 또는 "열기"를 붙여 실제 기온과 구분한다.

**한 사람이 한 번 올리면 오르는 양** = 10 × 점수 ÷ 평소값 (30분 동안 줄어 0이 됨)

| 장소 (평소값) | 점수 0.8일 때 |
| --- | --- |
| 맛집·카페 (5) | +1.6° |
| 시장 (10) | +0.8° |
| 축제·경기장 (20) | +0.4° |

**바꿀 곳**
- `lib/constants.ts`: `BASE_TEMP` 20 → 10
- `lib/temperature.ts` `band()`: 경계 20 / 30 / 40, 단계 이름 서늘·따뜻·폭염·대프리카
- `/api/course` 후보 기준: 30° 이상 → 20° 이상
- 단위 테스트 예시값, API 명세서 단계 표, 디자인 마커 색 구간

**03 장소 상세의 보조 숫자**

| 화면 문구 | 계산 | API 필드 |
| --- | --- | --- |
| 평소 대비 +12° | 현재 열기 − 20° (보너스 포함) | `vsBaseline` (신규) |
| 최근 참여 32명 | 최근 30분 안에 참여한 서로 다른 기기 수 | `peers30m` (신규). 기존 `peersNow`(5분)는 06 결과 화면용으로 유지 |

## 2. 로그인 — 확정

**글을 쓰는 순간에만 카카오 로그인을 묻는다.** 지도 보기, 장소 상세, 피드 보기, 열기 올리기는 로그인 없이 쓸 수 있다.

**흐름**
1. 06 "현장 사진 남기기" 또는 07 피드의 글쓰기 버튼을 누른다.
2. 로그인이 안 되어 있으면 바텀시트를 띄운다: "카카오로 3초 만에 로그인" + 닫기
3. 카카오 로그인 → 앱으로 돌아오면 **08 게시 화면으로 바로 이동**한다. 장소는 미리 선택된 상태로 둔다.
4. 로그인 상태는 유지되어, 다음 글쓰기부터는 바텀시트 없이 바로 08로 간다.

**글쓴이 표시**: 카카오 닉네임과 프로필 사진. 와이어프레임의 "익명 사용자" 표시는 없앤다.

**열기 발자국**: 이번에는 계정과 연결하지 않는다. 기기 기준(익명 deviceId)을 그대로 유지하고, 계정 연결은 발표 후에 한다.

**디자인에 추가할 것**
- 로그인 바텀시트 1장 (카카오 로그인 버튼, 닫기)
- MY 탭 상단에 로그인 상태 표시 (닉네임 또는 "카카오로 로그인")

**개발 메모**
- 로그인 후 돌아올 화면을 기억해야 한다 (예: `?next=/post?placeId=…`).
- 카카오 콘솔에 Redirect URI를 등록하고, Vercel 고정 프로덕션 주소로 테스트한다.

## 3. 게시물 구조 — 일부 확정

| 항목 | 결정 |
| --- | --- |
| 사진 개수 | **게시물당 1장** (확정) |
| 게시물 형태 (사진+글 / 댓글 여부 / 글만 허용) | **디자인과 협의 후 결정** (보류) |
| 열기 반영 방식 | **게시물 형태가 정해진 뒤 결정** (보류) |

**협의 때 볼 선택지**
- 형태
  - A. 와이어프레임대로 사진 + 글 = 게시물 1개, 댓글 없음
  - B. A + 게시물 댓글
  - C. 글만 쓰기도 허용
- 열기 반영 초안 (A 기준)
  - 게시물 1개 = 0.5점, 60분 동안 줄어듦
  - 같은 사람·같은 장소는 30분에 1개만 인정
  - 게시물로 오르는 열기는 최대 +10°

## 4. 카테고리 매핑 — 확정

와이어프레임 필터(전체 · 음식 · 축제 · 스포츠 · 기타)와 코드 카테고리 8개를 이렇게 묶는다.

| 화면 필터 | `group` 값 | 코드 카테고리 |
| --- | --- | --- |
| 음식 | `food` | food, cafe, market, night_market |
| 축제 | `festival` | festival, show |
| 스포츠 | `sports` | cheer |
| 기타 | `etc` | street |

- **매핑은 서버에서 한다.** `/api/places`, `/api/zones`, 피드 API가 장소마다 `group`을 함께 내려주고, 프론트는 그 값으로 거른다. 매핑을 바꿀 때는 서버 한 곳만 고친다.
- DB 카테고리 8개와 카테고리별 평소값(B)은 그대로 둔다.
- 07 피드 필터도 같은 `group` 값을 쓴다.

## 5. 일정 데이터 수집 — 확정 (K리그 인증키 확인 중)

**구조**: 외부 일정을 스크립트로 모아 `schedules` 테이블에 넣는다. 사용자 요청 때는 외부 API를 부르지 않는다.

```
scripts/sync-schedules.ts  (하루 1번 또는 손으로 실행)
 ├─ KBO: KBO 사이트 일정 데이터 → 삼성 + 구장 "대구"만
 ├─ K리그: meetSchedule.do → 대구FC 홈 경기만
 ├─ 축제: 전국문화축제표준데이터 CSV → 주소에 "대구"가 들어간 행만
 ├─ 버스킹 등: data/schedules-manual.csv (손으로 입력)
 └─ 장소 연결 → schedules에 upsert (source + external_id로 중복 방지)
```

```sql
create table schedules (
  id          bigserial primary key,
  place_id    uuid not null references places(id) on delete cascade,
  title       text not null,
  starts_at   timestamptz not null,
  ends_at     timestamptz not null,
  source      text not null,          -- kbo | kleague | festival | manual
  external_id text not null,
  unique (source, external_id)
);
```

| 소스 | 가져오는 방법 | 일정 시간 처리 | 상태 |
| --- | --- | --- | --- |
| KBO | `POST https://www.koreabaseball.com/ws/Schedule.asmx/GetScheduleList` (form: `leId=1&srIdList=0,9,6&seasonId=연도&gameMonth=MM&teamId=SS`), 월마다 1번 요청 | 시작 1시간 전 ~ 시작 후 3시간 30분 | **확정** |
| K리그 | `GET https://api.kleague.com/api/meetSchedule.do?meet_year=&meet_seq=` + `authKey` | 시작 1시간 전 ~ 시작 후 2시간 30분 | **인증키 백엔드 확인 중**. 키가 없으면 대구FC 홈 경기를 수동 CSV로 입력 |
| 축제 | [전국문화축제표준데이터](https://www.data.go.kr/data/15013104/standard.do) CSV 다운로드 (분기 갱신, 무료) | 날짜만 있으므로 그날 10:00~22:00 | 확정 |
| 버스킹 등 | `data/schedules-manual.csv` | 직접 입력 | 확정 |

**장소 연결 (카카오맵)**
- **경기장:** 외부 이름과 우리 장소 이름이 달라서 `data/venues.csv`에 "외부 이름 → 우리 장소"를 적는다. 예: KBO 구장 "대구" → 삼성라이온즈파크
- **축제:** CSV의 위경도로 우리 장소 중 300m 안의 장소에 붙인다. 없으면 카카오 로컬 검색으로 좌표를 찾아 새 장소(`festival`)로 추가한다.

**KBO 데이터 주의**
- 공식 공개 API가 아니라 KBO 사이트 내부용 주소다. 형식이 바뀌거나 막힐 수 있고, 응답 일부가 HTML 조각이라 글자만 뽑아 써야 한다.
- 데모처럼 가볍게 쓰는 수준으로만 쓴다. 정식 서비스는 KBO 문의나 데이터 제휴(스포츠투아이 등)를 검토한다.
- 2026 시즌이 끝나서 발표 때 경기가 없다. 데모에서는 9월 라팍 경기 하나를 "오늘"로 바꿔 넣어 연출한다.

## 6. 열기 올리기 참여 방식 (05) — 확정

**연타 5초 → 흔들기 5초, 순서대로.** 전체 10초.

```
[시작] 버튼 (아이폰은 여기서 흔들기 권한 요청)
 → 3, 2, 1
 → ① 연타 5초  "버튼을 마구 눌러요!"
 → ② 흔들기 5초 "이제 폰을 흔들어요!"
 → POST /api/heat → 06 결과
```

| 항목 | 결정 |
| --- | --- |
| 점수 | 0.7 × min(연타 수 ÷ 25, 1) + 0.3 × 흔들기 세기 (그대로) |
| 연타 상한 | 40회(10초) → **25회(5초, 초당 5회)**. 초당 4회는 대부분 채워서 차이가 안 나므로 조금 높임. 실기기로 확인 후 조정 |
| 흔들기 세기 | 흔들기 5초 동안의 평균으로 계산 |
| 센서 없음·권한 거부 | 흔들기 단계를 건너뛰고 연타만으로 최대 1점 (`shake: null`로 전송) |
| 서버 검증 | taps 0~200 그대로 받고, 점수 계산 때 상한으로 자름 |

**바꿀 곳**
- `lib/constants.ts`: `MAX_TAPS` 40 → 25
- `lib/temperature.ts` `eventScore()`: `shake`가 null이면 연타만으로 계산
- `POST /api/heat`: `shake`에 null 허용
- `/heat/[placeId]` 화면: 시작 버튼, 카운트다운, 두 단계 진행 표시
- 디자인: 05를 단계 두 개로 나누고, 시작 화면과 3·2·1 카운트다운 추가

## 7. 기능 포함 여부 — 확정

화면 구성은 디자인 파트와 협의 후 진행한다. 여기서는 넣을지 말지와 동작 규칙만 정한다.

| 2 | MY: 발자국 작은 지도 | 빼기 | — |

## 8. 지도 — 확정 (A안: 카카오맵 + 피그마 스타일)

**바탕 지도는 카카오맵을 그대로 쓰고, 그 위에 얹는 요소만 피그마 디자인대로 다시 그린다.** 일러스트 지도(B안)는 하지 않는다.

[A안 썸네일](https://claude.ai/artifact/9AApM4QefQwYt1JoRwBjX5)

| 화면 | 그대로 | 바뀌는 것 |
| --- | --- | --- |
| 01 구역 보기 | 카카오맵 바탕, 현재 위치, 카카오 로고 | 구역 원: 반투명 원 + 큰 온도 + 구역명, 색은 새 4단계 |
| 02 장소 보기 | 카카오맵 바탕 | 마커: 온도 + 장소명 알약 모양. 필터는 `group` 4개. 하단 목록 시트(02-B) 새로 만듦 |
| 03 장소 상세 | 위쪽 지도 일부 | 피그마 바텀시트: 현재 열기, 평소 대비, 최근 30분 참여, 사진, 열기 올리기, 다음 갈 곳 |

- **이유:** 남은 시간이 짧고, 위치가 정확하며, 열기 코스 선과 현재 위치 같은 기존 기능을 그대로 쓸 수 있다.
- **한계:** 카카오맵의 바탕색과 도로 스타일은 바꿀 수 없다.
- **바꿀 코드:** `HeatMarker`, `ZoneLayer`, `PlaceSheet`의 모양만 바꾼다. `KakaoMap`은 그대로 둔다.
- **지킬 것:** 바텀시트가 카카오 로고를 가리지 않게 한다.
